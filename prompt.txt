You are the lead software architect and senior Python engineer responsible for building a powerful desktop AI agent called **FLEX**.

## 1. PROJECT VISION

Build FLEX as a JARVIS-like desktop AI agent for Windows.

FLEX should be able to understand natural-language commands from the user and actually perform tasks on the computer rather than merely explaining how to perform them.

Examples:

* "Open Chrome."
* "Open VS Code."
* "Find the Downloads folder."
* "Create a folder called Projects on my desktop."
* "Open this website."
* "Search YouTube for Blender tutorials."
* "Type this message."
* "Take a screenshot."
* "Open Notepad and write this."
* "Close Chrome."
* "Increase the volume."
* "Find this file."
* "Move this file to another folder."
* "Open PowerShell and run a safe command."
* "Go to GitHub and open my repository."
* "Look at what is currently on my screen."
* "Do this sequence of tasks..."
* "If something fails, figure out why and try another method."

FLEX should be an actual computer-use agent.

The AI model is the BRAIN.
FLEX is the AGENT/OPERATING LAYER.
Tools are the HANDS.
Screenshots, UI Automation and browser inspection are the EYES.
Memory is the CONTEXT.
The security/permission system is the SAFETY LAYER.

Do NOT build FLEX as a chatbot that only responds with instructions.

USER
↓
FLEX UI

↓
AGENT ORCHESTRATOR
↓
LLM PROVIDER
↓
STRUCTURED TOOL CALL
↓
SECURITY / PERMISSION LAYER
↓
TOOL EXECUTION
↓
WINDOWS / BROWSER / FILESYSTEM / TERMINAL
↓
OBSERVATION
↓
VERIFICATION
↓

# 6. AGENT LOOP

Implement the core loop:

USER REQUEST
→ UNDERSTAND
→ PLAN
→ TOOL CALL
→ SECURITY CHECK
→ EXECUTE
→ OBSERVE
→ VERIFY
→ CONTINUE OR FINISH

For example:

User:
"Open Chrome and search YouTube for Blender tutorials."

Possible internal sequence:

1. Understand request.
2. Open Chrome.
3. Verify Chrome opened.
4. Navigate to YouTube.
5. Verify page loaded.
6. Search for Blender tutorials.
7. Verify search results.
8. Tell the user the task is complete.

The agent should NOT simply assume an action worked.

Every important action should have verification where practical.

---

# 7. MULTI-STEP TASKS

FLEX must support multi-step tasks.

Example:

"Open Chrome, search Google for Blender, open the first result, and take a screenshot."

The agent should be able to:

1. Break the task into steps.
2. Execute one step.
3. Observe the result.
4. Decide the next step.
5. Recover if a step fails.
6. Finish only after verification.

Do not generate an enormous plan and blindly execute it.

Prefer:

PLAN → ACTION → OBSERVE → NEXT ACTION.

# 17. SECURITY / PERMISSION SYSTEM

Create permission levels:

READ_ONLY
LOW_RISK
MEDIUM_RISK
HIGH_RISK

Examples:

READ_ONLY:

* screenshot
* list files
* inspect windows
* inspect processes

LOW_RISK:

* open application
* focus window
* navigate browser
* type normal text

MEDIUM_RISK:

* move files
* rename files
* install software
* modify settings

HIGH_RISK:

* delete files
* shutdown
* restart
* system-level changes
* commands that could cause data loss

High-risk actions require explicit user confirmation.

The model must NEVER be able to bypass the permission system.

Security checks must happen locally before execution.

# 19. VERIFICATION

FLEX must distinguish between:

ACTION REQUESTED
ACTION EXECUTED
ACTION VERIFIED

Never tell the user:

"Done."

unless there is reasonable evidence that the requested action succeeded.

Example:

If FLEX requests:

open_application("chrome")

verify that a Chrome window/process actually appeared.

If it did not:

* report failure
* attempt safe recovery if appropriate
* avoid falsely claiming success

# 31. FIRST MILESTONE

The first working version should support:

1. Start FLEX.
2. Show the PySide6 interface.
3. User types a request.
4. FLEX sends the request to OpenRouter.
5. AI decides whether a tool is required.
6. AI requests a structured tool.
7. FLEX validates the tool.
8. FLEX checks permissions.
9. FLEX asks for confirmation when required.
10. FLEX executes the tool.

12. FLEX verifies success.
13. FLEX sends the result back to the AI.
14. AI decides whether another action is required.
15. FLEX completes the task.
16. UI displays the result.

"Create a folder called FLEX_TEST on my Desktop."

"Take a screenshot."

These should work through the actual tool system, not fake responses.
